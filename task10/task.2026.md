# Задание №10

Выбрать используемый вариант задания:

1. DevSecOps – разработка CI/CD-конвейера с проверками SAST и DAST.
2. AppSec – провести проверку фаззером или реализовать фаззинг отдельных функций.
3. SDL – разработать приложение с ролевым доступом в PostgreSQL через SSO, хранилище секретов или другим способом.

## Вариант 1:

1. Выбрать один из способов построить CI/CD-конвейер: GitLab / GitFlic, GitHub Actions / GitVerse / Jenkins или др.
2. Выгрузить код задания 7 в ветку на Git-платформу.
3. Используя наработки 8 практической работы, автоматизировать проверку одним из SAST-средств на этапе Push в любую ветку через CI/CD-конвейер.
4. Используя наработки задания 9 практической работы, автоматизировать проверку DAST-средством на этапе Push / Merge в основную ветку разработки (develop) через CI/CD-конвейер.
5. Автоматизировать проверку SAST- и DAST-средствами при Push / Merge в основную продуктивную ветку (main / master).

### Требования для сдачи приложения:

1. Продемонстрировать отчёты о проверке по каждому из 3 событий: Push в feature-ветку – отчёт с результатами SAST, Merge в ветку develop – отчёт с результатами DAST, Merge в ветку main – отчёт с результатами SAST- и DAST-проверки.
2. Ответить на вопросы преподавателя.

## Вариант 2:

1. Выбрать один из используемых подходов к фаззингу:
   1. Внешний фаззинг через приложение, например: AFL++, WinAFL.
   2. Или реализация фаззинг-тестов через встраиваемую библиотеку, например: libFuzzer, sharpfuzz (dotnet), testing.F.Fuzz (go).
2. Выбрать фаззируемый объект – им может быть как код из 3 практического задания, 7 практического задания, так и любая используемая Open Source-библиотека для вашего языка программирования.
3. Составить план фаззинг-тестирования:
   1. Определить исследуемые функции на поверхности атаки.
   2. Определить начальный корпус для фаззинга, чтобы покрыть очевидные условные переходы исследуемого кода.
   3. Оформить план фаззинга в виде таблицы или списка.
4. Если используется фаззинг через библиотеку, написать фаззинг-тесты на языке программирования исследуемого кода.
5. Провести фаззинг-тестирование.
6. Оформить отчёт по результатам фаззинг-тестирования, описав:
   1. Удалось ли что-либо найти фаззеру.
   2. Какие из найденных путей (входных параметров) ведут к обработанным ошибкам.
   3. Какие из найденных путей (входных параметров) ведут к необработанным ошибкам.
   4. Какие из найденных путей (входных параметров) ведут к потенциальным уязвимостям.

### Требования для сдачи приложения:

1. Продемонстрировать исходный код для фаззинг-тестов или обосновать выбор используемых фаззинг-утилит, параметры их запуска и начальный корпус параметров.
2. Продемонстрировать отчёт о фаззинг-тестировании.
3. Ответить на вопросы преподавателя.

## Вариант 3:

На основе исходных кодов 3 или 7 практической работы реализовать доступ приложения с подключением к СУБД PostgreSQL. Исходные условия:

1. Пользователь приложения аутентифицируется через отдельное приложение или SSO. При аутентификации получает JWT Access- и Refresh-токены.
2. После аутентификации пользователь получает доступ к нескольким модулям для работы с БД, каждый модуль работы с БД на PostgreSQL имеет свою роль (права) внутри БД на PostgreSQL.
3. Задача — разработать и реализовать такое приложение, которое по полученному JWT-токену предоставляло бы доступ к БД на PostgreSQL таким образом, что:
   1. Можно было бы идентифицировать, какой изначально пользователь получил доступ к БД (его email или login в приложении аутентификации или SSO).
   2. Можно было ограничить доступ к таблицам / функциям БД на основе того, какой модуль приложения сейчас взаимодействует с БД.
   3. Способ аутентификации в БД был ограничен доступом максимум до 1 дня, без повторной аутентификации в SSO или отдельном приложении (возможна повторная упрощённая аутентификация по Refresh Token JWT).
   4. Это должно быть безопасно.
4. При разработке решения использовать знания о:
   1. SSO (Keycloak).
   2. Хранилищах секретов (HashiCorp Vault, Kubernetes Secrets, Infisical).
   3. SSL-сертификатах.

   Но эти знания вас не ограничивают, можете предложить другой способ решения задачи.

5. Реализовать предложенное решение в виде прототипа, демонстрирующего разработанный подход.

### Требования для сдачи приложения:

1. Продемонстрировать исходный код приложения и работу прототипа.
2. Ответить на вопросы преподавателя.
