# Задание №3

1. Выбрать любую предметную область.
2. Для неё спроектировать БД минимум из 4 связанных таблиц.
3. Подготовить SQL-скрипты для создания спроектированной БД.
4. Подготовить тестовые SQL-скрипты или приложение (Unit-тест) для заполнения БД демонстрационными данными.
5. Настроить права пользователя, отличного от администратора БД и СУБД, для доступа в созданную БД.
6. На основе кода, разработанного в практическом занятии 1, разработать программу:
   1. Позволяющую пользователю просматривать таблицы:
      1. Без фильтрации. Пример:

         ```sql
         SELECT * FROM table;
         ```

      2. С фильтрацией по одному значению: пользователь может тем или иным способом указать не только значения для фильтрации, но и колонку, по которой идёт фильтрация. Пример:

         ```sql
         SELECT * FROM table WHERE @id = $id;
         ```

         Здесь и далее:

         - `@v` – это название колонки, получаемое от пользователя,
         - `$id` – значение для колонки, получаемое от пользователя.

      3. С фильтрацией по нескольким значениям. Пример:

         ```sql
         SELECT * FROM table WHERE id = @id AND @value = $value;
         ```

   2. Позволяющую пользователю обновлять:
      1. Одну запись, изменяя любые поля, кроме Id; пользователь может указать, какие колонки и на какие значения он может обновить. Пример:

         ```sql
         UPDATE SET @value = $value, @cost = $cost, … WHERE id = $id;
         ```

      2. Изменять несколько записей, указав для них общее новое значение. Пример:

         ```sql
         UPDATE SET @cost = $cost WHERE @value IN ($value1, $value2, …);
         ```

   3. Позволяющую пользователю вносить:
      1. Одну строку в таблицу. Пример:

         ```sql
         INSERT INTO (id, value, cost) VALUES ($id, $value, $cost);
         ```

      2. Одну строку в несколько связанных таблиц. Пример:

         ```sql
         INSERT INTO table(id, value, cost) VALUES ($t_id, $value, $cost) RETURNING id;

         INSERT INTO list(id, t_id, count, price) VALUES ($l_id, t_id, $count, $price);
         ```

         Здесь значение для вставки в поле `list.t_id` получается из предыдущей вставки в таблицу `table`, поле id.

   4. Позволяющую пользователю вносить:
      1. Несколько строк в одну таблицу.
      2. Несколько строк в несколько связанных таблиц – задание повышенной сложности.
   5. Факт успешного или неуспешного подключения к БД, выполнения запроса в БД должен записываться в соответствующий поток вывода stdout / stderr, при этом текст ошибки должен быть дружественным пользователю — скрывающим детали реализации (типичные ошибки фреймворка, ошибки от БД).
   6. Логин и пароль, необходимые для подключения к БД, получаем от пользователя.
   7. Приложению через переменную среды окружения дополнительно можно передать путь к файлу, куда будут дублироваться логи, в чистом виде, без дополнительной обработки для пользователя.
   8. Написать Dockerfile, который упаковывает скомпилированное / интерпретируемое приложение и все необходимые для его работы зависимости, в том числе файл конфига.
   9. Приложение должно выполняться в одной сети Docker с образом СУБД, но поддерживать интерактивный режим для работы пользователя.
   10. Написать Env-файл для Docker, содержащий работающие примеры значений переменных среды (пункт 6.7) для демонстрации.
   11. Собрать тегированный образ Docker на основе файла Dockerfile.
   12. Подключить собранный образ в Docker Compose с PostgreSQL Docker-образом, передав параметром путь до Env-файла.
   13. При реализации программы обеспечить безопасную передачу параметров и названий колонок в SQL-запросы. Особенно требуется обратить внимание на безопасность передачи в SQL-запросы названий колонок и групп однородных данных для фильтрации или вставки.

## Требования для сдачи приложения:

1. Расположить SQL-скрипты, код для заполнения БД, исходный код программы, Dockerfile, Env-файл, Docker Compose-файл в отдельный публичный репозиторий или в отдельную ветку предыдущего репозитория.
2. Продемонстрировать работу приложения, пункты 6.1–6.4.
3. Ответить на вопросы преподавателя.
